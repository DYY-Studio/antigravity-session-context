# Cross-Conversation & Subagent Context Lookup (`session-context`)

When the user asks to reference, search, or inspect another conversation, **or when you need to audit, debug, or collect metrics on subagents** (including subagents spawned in the current conversation whose `invoke_subagent` output includes `logAbsoluteUri`):

1. **Always use `session-context_mcp` MCP tools instead of writing Python/shell scripts or calling `read_file` on transcripts or `.db` files**:
   - `get_conversation_context({ conversation_id?, conversation_ids?, include_subagents? })`: Inspect exact context window usage, 256k compaction budget watermark (`budget_used / 256k` and remaining headroom before auto-compaction), per-category token breakdown (`User`, `Agent`, `Tool calls`, `System`, `Rules`, `Skills`, `MCP tools`), checkpoint compactions, and live run state from `conversations/<id>.db`. Pass a parent `conversation_id` to inspect both the parent and all spawned subagents at once, or pass `conversation_ids` to batch-inspect specific subagents.
   - `list_conversations({ workspace?, limit?, include_subagents?, parent_conversation_id? })`: List recent conversations, or pass `parent_conversation_id` to get all subagents of a conversation with their extracted `Role`, resolved model, `steps`, `turns`, `tools`, `duration`, live `state`, and compact `ctx` / `budget` watermark.
   - `search_conversations({ query, workspace?, parent_conversation_id?, limit?, max_chars? })`: Search across titles, user requests, agent responses, and subagent transcripts (`|` separates OR phrase alternatives; without `|`, space-separated tokens are ANDed; returns matching `conversation_id`, capped snippets, and `matched_steps`).
   - `get_conversation_digest({ conversation_id, query?, start_step?, end_step?, max_chars?, include_tools?, include_thinking?, include_tool_outputs?, include_system_messages?, include_subagents? })`: Retrieve a low-token digest with execution & context budget metrics, artifacts, subagent role/metric/budget summaries, and tool calls annotated with `[Step N]` / `[Step N, exit=1]` result indices, `read_file` line ranges, and `<Server>.<Tool>(...)` arguments (automatically restoring truncated `content`, `thinking`, and `tool_calls` from `transcript_full.jsonl`). Pass `query` (e.g. `"region_id|keyword"`) to filter matching steps; omit `include_thinking` to attach a compact thinking snippet only when a step matches solely via thinking (set `false` to skip thinking in both search and output, `true` for full thinking); pass `include_tool_outputs: true` with `query` to search raw `GENERIC` tool outputs and return compact match windows with calling context.
   - `get_conversation_step({ conversation_id, step_index?, step_indices?, full?, offset?, max_chars? })`: Inspect the raw tool output or full untruncated JSON of a single `step_index` or a batch of `step_indices` (e.g. `[14, 16, 31]`) in one call; multi-step batches at `offset=0` fairly allocate budget so short steps stay intact while large steps return previews with exact single-step continuation offsets.
   - **Keep default inline budgets (`max_chars` omitted = 8,000 chars / 9.2 KB UTF-8)** during scans and batch lookups so responses stay inline instead of spilling to `.system_generated/steps/*/output.txt`; only pass larger `max_chars` (up to `100000`) when intentionally pulling a large dump.
2. **Never read or parse raw `transcript.jsonl`, `transcript_full.jsonl`, or `conversations/*.db` with `read_file` or custom `python -c` scripts** unless the `session-context_mcp` tools are unavailable. Raw transcripts contain large `GENERIC` tool outputs and truncated fields in `transcript.jsonl` that `session-context_mcp` automatically handles and upgrades from `transcript_full.jsonl`.
